# Thinking Model Engine

> 为 OpenClaw Agent 提供“事实 → 最小模型处方 → 可验证行动”的判断引擎。

[![OpenClaw Skill](https://img.shields.io/badge/OpenClaw-Skill-blue)](https://github.com/openclaw/openclaw)

## 它解决什么问题

Thinking Model Engine 适用于需要判断、取舍或设计验证的具体问题，例如：

- 该选哪个方案，还缺什么信息？
- 团队的工期估算是否过度乐观？
- 产品数据的变化是因果效果，还是相关和混杂？
- KPI 为什么越优化，真实结果越差？
- 上线、迁移或流程改造前如何系统排查失效路径？
- 冲突中怎样说清事实、需要、请求和边界？

它不是把一长串模型名丢给用户的索引器。默认只使用 **1 个主模型 + 0–2 个补充模型**，并要求每个模型都改变一个具体判断或行动。

## 核心改进

- **证据优先**：明确区分已验证事实、假设、模型推论和未知。
- **最小处方**：避免用 5–8 个重叠模型制造“全面”错觉。
- **弱证据降级**：个人启发式不承担重大决策的主结论。
- **可验证行动**：优先给可逆试点、证据需求、扩大/停止/回滚条件。
- **不伪造精度**：没有数据时不编造概率、收益、工期和固定时间线。
- **渐进加载**：先读触发索引，再读选中模型，不把全库塞进上下文。

模型数量由验证器从文件系统统计，并与目录唯一覆盖关系核对；仓库同时包含目录、触发索引和维护规范。

│   └── test_validate_skill_metadata.py # 元数据校验器负向回归

## 主要能力

| 能力域 | 代表模型 |
|--------|----------|
| 决策与不确定性 | 参考类预测、信息价值、期望值计算、贝叶斯思维、安全边际 |
| 原因与实验 | 5W 问题描述法、5 Whys、因果推断、问题树 |
| 风险与可靠性 | 逆向思维、FMEA、冗余备份、反脆弱 |
| 系统与流动 | 系统思维、反馈回路、约束理论 TOC、Cynefin |
| 产品与验证 | Jobs to Be Done、设计思维、MVP、RICE |
| 目标与指标治理 | OKR、OGSM、古德哈特定律、PDCA |
| 委派与治理 | 交易成本经济学、委托—代理问题、约束理论 TOC |
| 沟通与冲突 | 非暴力沟通 NVC、非 SR 思维、乔哈里视窗、PREP |
| 学习与行动 | 费曼学习法、间隔重复、刻意练习、元认知、WOOP |

## 证据分级

`models/02_维护规范.md` 定义了三类内容：

| 级别 | 定位 | 用法 |
|------|------|------|
| A | 有原始文献、标准或稳定理论基础 | 可作为主模型，仍要遵守适用边界 |
| B | 可追溯的实践框架 | 用于结构化实务，不写成普遍因果规律 |
| C | 来源不足或自定义启发式 | 只做创意提示，不承担重大结论 |

## 使用示例

```text
“我们要做一次核心 API 迁移，团队说 5 个月能做完，
但历史上类似项目都延期。该全面开工还是先试点？”
```

Skill 会优先区分：

1. 历史项目数据是已知事实还是印象。
2. 参考类预测能否提供工期基准。
3. 试点信息是否足以改变全面开工决定。
4. 什么条件下扩大、停止或回滚。

## 验证

```bash
./scripts/validate_skill.sh
```

验证器检查：

- `SKILL.md` 元数据和长度。
- 目录是否唯一覆盖所有模型文件。
- 本地 Wiki 链接是否存在。
- Markdown 一级标题和代码围栏是否完整。
- 冻结豁免身份的数量与 SHA-256 是否未变，实际债务是否仅为其子集，并如实拆分治理状态。
- 旧命名和过期模型数量是否回流。
- 评测 JSON 的结构、唯一编号、最小断言数量，以及委派决策、并行、委托—代理和历史证据债务场景是否都有声明覆盖。

GitHub Actions 会在 push 和 pull request 时运行 Bash 语法、JSON 解析、技能元数据快速校验和上述验证器。它只守住确定性结构底线：`evals.json` 的用例仍需要在具备实际模型运行环境时执行和人工判读，CI 不证明模型内容质量、真实委派行为或端到端结果。

## 维护原则

1. `models/00_目录.md` 是模型名称和文件映射的 SSOT，不再维护第二份手写速查表。
2. `models/01_触发索引.md` 是场景路由 SSOT，不再维护重复处方书。
3. 新增、删除或重命名模型后，必须同步目录与触发索引，并运行验证器。
4. 组合配方只记录跨阶段、不重复的分工，不为每个场景堆模型。
